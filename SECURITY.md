# 🛡️ Security Policy

Project Guard is dedicated to maintaining high standards of cybersecurity, memory safety, and responsible vulnerability disclosure.

## Supported Versions

Only the latest release is actively supported with security patches:

| Version | Supported          |
| ------- | ------------------ |
| 1.1.x   | :white_check_mark: |
| 1.0.x   | :x:                |
| < 1.0   | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability in Project Guard, please report it responsibly:

1. **Do NOT open a public GitHub issue.** Public issues disclose zero-day details before a fix is ready.
2. Please use **[GitHub Private Vulnerability Reporting](https://github.com/kilic/project-guard/security/advisories/new)** to submit your report confidentially.
3. Alternatively, email the security response team at `security@projectguard.dev` or reach out via secure channels.

### Information to Include
* Description of the vulnerability and attack vector.
* Minimal reproduction steps or Proof-of-Concept (PoC).
* Potential impact on endpoint defense or privilege escalation risks.

### Vulnerability Response Timeline
* **Initial Acknowledgement:** Within 24-48 hours.
* **Assessment & Reproduction:** Within 5 business days.
* **Remediation & Patch Release:** Prioritized based on CVSS severity score.
* **Public Disclosure:** Coordinated with the reporter after the fix is published.
